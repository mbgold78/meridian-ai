Homepoc shipped **UI only**: `BeaconAgent` fixture rows rendered by `OperationsTab` (fleet stat strip, status-pill rows, click-through deployment panel). ## 2. Decision — architecture in one paragraph

A conventional Spring/JPA engine in `engine/src/main/java/com/meridian/substrate/engine/agent`, entities in `common.domain`, repositories in `common.repo`, controllers in `app.api.v1`, migration `common/V6__agent_registry.sql` + `postgresql/V6_1__agent_registry_postgres.sql`. Truth for everything that *happened* lives in an **append-only `agent_status_events` table**; the `agent_registrations` row carries rebuildable projections (operational mode, liveness, control-confirmation, event_seq fencing) — the ratified cascade D1 idiom, with an `AgentProjectionRebuilder`. A registration is born only at the DEPLOY act with [AGENT-PROVENANCE] fields as NOT NULL columns — a provenance-less agent row cannot exist. The state model is **two-dimensional**: `operational_mode ∈ {SHADOW, LIVE, PAUSED, RETIRED}` plus a zero-or-more open-interventions overlay; the wire `status` is a pinned-precedence projection serialized in the exact fixture vocabulary. The operator-facing core is an **honest verb model**: every Ops Center verb (pause / resume / throttle / kill / retire / promote / intervene) always produces (a) an attributed append-only event, (b) an authoritative substrate governance-state change, and (c) one of exactly two declared enforcement effects by `execution_locus` — `GATEWAY_BLOCK` (the agent's actions transit `ContractGateway` as AGENT principals and are denied from the next call) or `RECORDED_INTENT` (substrate cannot reach the runtime; the verb records intent, notifies the oversight chain via a transactional outbox, and tracks runtime acknowledgment and human-attested confirmation as first-class pending states). Verb responses and the detail DTO disclose which effect applies BEFORE and AFTER the click; the UI never renders fabricated control. Liveness is strictly evidence-derived from a separate `agent_sightings` telemetry table. deploymentCriteria is immutable post-deploy, digest-anchored into the decision-log hash chain, and made a runtime gate via `agent_criteria_gates` reusing the contracts TinyDsl verbatim — signal-only, never auto-suspending. Gateway integration rides an `AgentRegistryGate` SPI (no-op default in `engine.contract.gateway`, real `@Primary` impl in `engine.agent`) so whole-or-in-part holds by construction. Zero orchestrator touchpoints exist in the engine; mandate-bearing dispatches bind by provenance digest, and dispatch results attributable to killed/paused registrations are refused at the existing `apply_dispatch_result` PEP.

## 3. Decisions

### D1. Core shape: JPA aggregate + append-only event log + rebuildable projections (cascade D1 idiom, reused wholesale)

**Decision.** `agent_status_events` is append-only (PG trigger in V6_1; H2 dev service-enforced, V4_1/V2_1 precedent) and is the audit source of truth for every lifecycle/control/oversight fact. `agent_registrations` projection fields (operational_mode, mode_before_pause, open_intervention_count, control-confirmation block, liveness block, retired block, event_seq) are updated synchronously in the same transaction and deterministically rebuildable by `AgentProjectionRebuilder`. All mutations: PESSIMISTIC_WRITE on the registration row, mandatory client `idempotencyKey` (`UNIQUE(agent_registration_id, idempotency_key)`), optional `expectedEventSeq` → 409 `AGENT_STALE_STATE` (cascade D8 verbatim).

**Alternatives considered:** event-sourced core with per-agent hash chain (rejected for the same reasons as cascade D1 — implementation risk on the JPA base; the bounded decision-log mirror in D14 covers tamper-evidence where it matters); plain mutable rows (rejected — P12 control claims without an attributed event trail are unauditable assertions).

**REVISIT TRIGGER:** same as ADR-001 D1 — tamper-evidence demands hardening beyond the D14 mirror.

### D2. Two identities, never conflated: durable registered agents vs ephemeral orchestrator workers (*graft*)

**Decision.** The registry holds **durable deployed agents** (the Curasync Pre-Visit Intake Assistant class: operational agents at the customer, governed parties on the MCP surface). **Ephemeral orchestrator workers** (dispatched via `submit_task` for AI assist — cascade draft suggest today, diagnostic generation in Phase 4) are NOT auto-registered; their output enters substrate as suggestions or via the `apply_dispatch_result` PEP under `Principal(SERVICE, substrate-svc)` with provenance digests on the consuming record, exactly as ADR-002 D2 already defines. The bridge: when substrate dispatches work **on a registered agent's mandate**, the dispatch context pack includes the agent's `agent_key` + instruction to present `X-MCP-Principal: <mcp_principal_id>` on substrate calls, and substrate writes a `DISPATCH` event row on that agent's log carrying the standard provenance-digest shape (`{taskId, model, eventsDigest, requestedAt, landedAt}` — same JSON shape `cascade_drafts.suggestion_provenance` already persists). `agent_registration_id` is the stable identity; orchestrator task ids are per-dispatch ephemera digested into the agent's audit trail. **The orchestrator never learns any of this exists** — identity binding is 100% substrate-side, in the context pack out and the principal header back.

**Alternatives considered:** auto-registering every dispatched worker (rejected — floods the registry with non-governance ephemera and would demand provenance fiction for machine-spawned workers); making orchestrator dispatch ids first-class registry identities (rejected — couples registry identity to a seam that must stay substrate-unaware).

**REVISIT TRIGGER:** first Phase-4 mandate-bearing dispatch; if per-dispatch query patterns emerge, promote DISPATCH event rows to a dedicated `agent_dispatches` table (cheap pre-first-customer).

### D3. Spec unification: one aggregate; provenance is structural; supervisoryModel required as a unification posture; readiness provenance recorded (*graft: readiness_source*)

**Decision.** One `agent_registrations` table unifies the BeaconAgent provenance fields with doc-06 `AgentDeploymentSpec` ([AGENT-SPEC-UNIFICATION]): `target_process_id`, `target_step_ids`, `agent_readiness_score`, `required_system_access`/`required_data_access`, `supervisory_model`, plus reserved nullable `initiative_id` (the plan engine does not exist yet — S4-class seam, soft ref). Provenance columns (`deployed_by_label`, `deployed_at`, `deployment_criteria`, ≥1 ordered `agent_oversight_links` row) are **NOT NULL / hard-validated at `POST /agents`** with per-field 400 codes — a provenance-less agent is structurally impossible, not policy-checked. `supervisory_model` and `execution_locus` are also API-required, **documented as an [AGENT-SPEC-UNIFICATION] posture, not an [AGENT-PROVENANCE] requirement** (the binding provenance block names only four fields). Substrate records, displays, and publishes `supervisory_model`; it enforces nothing it would have to invent — `HUMAN_REVIEW_ABOVE_THRESHOLD` threshold semantics are defined nowhere (flag-not-invent, spec §17). `agent_readiness_score` carries a `readiness_source ∈ {READINESS_LENS, OPERATOR_ASSERTED}` sibling so a caller-asserted score is never laundered as a deterministic lens computation (P7 discipline). P11 safety defaults land as data: `read_only=true` default, `schedule_window`, `sampling_pct`, born-SHADOW (D4).

**Alternatives considered:** separate spec table keyed by initiative (rejected — `initiativeId` points at an engine that doesn't exist; fixtures bind capability, not plan); making supervisory_model nullable (rejected — the unification block names it, and a recorded-but-absent supervision posture is worse than an explicit one); deriving readiness from `process_steps.agent_readiness_score` silently (rejected — recorded as the READINESS_LENS path *when the caller computes it that way*; v1 never fabricates the computation).

**REVISIT TRIGGER:** plan engine landing (initiative intake); first engagement defining threshold semantics for HUMAN_REVIEW_ABOVE_THRESHOLD.

### D4. Two-dimensional state: operational_mode + intervention overlay; wire status is a pinned-precedence projection; RETIRED is the flagged fifth wire value

**Decision.** The fixture conflates machine state and attention state; the registry separates them. `operational_mode ∈ {SHADOW, LIVE, PAUSED, RETIRED}` is the machine state; open `agent_interventions` rows are the attention overlay — **an agent in intervention is typically STILL RUNNING** (verified fixture truth: No-Show Predictor); pausing it is a separate, explicit, separately-evented operator act. The wire `status` is a projection with pinned precedence — `retired` → else `paused` → else open intervention ⇒ `intervention-required` (the fixture literal) → else `shadow`/`live` — serialized via `@JsonValue` in exact fixture vocabulary, pinned by contract test BEFORE the 6a swap. Deploy lands SHADOW by default (P11 #6 observation-only trial); deploy-to-LIVE requires explicit `liveJustification` recorded on the DEPLOYED event. RETIRED is terminal-absorbing, reached by **kill** (emergency, reason mandatory, `retired_reason=KILLED`) or **retire** (orderly, `retired_reason=RETIRED`); both are legitimate human governance acts returning 200, never error-colored. `retired` rows are **EXCLUDED from `GET /agents` by default** (`?includeRetired=true` opt-in) because the swapped OperationsTab pill map crashes on unknown statuses; the frontend extends the union only when it adopts the retire affordance. Re-deploy after retirement = a new registration with `predecessor_registration_id` lineage (D5).

This adds vocabulary beyond the binding [AGENT-STATES] four. Justification is P12, not fixtures: "killable" without a persistent resulting state is incoherent, and deletion would destroy the audit record. **Flagged for Mike — not silently invented.** The kill-vs-retire distinction (one enum value + `retired_reason`) is likewise flagged. Fallback if overruled: collapse to four wire values + `retiredAt` flag — a projector-only change thanks to D1.

**Alternatives considered:** single five-value enum with KILLED (both losing designs; rejected — flattens the verified mode/attention distinction and misrenders the No-Show Predictor); intervention as a mode (rejected — same flattening); including retired in fleet lists with a frontend union patch in the same chunk (rejected — cross-repo coordination risk for zero 6a value).

**REVISIT TRIGGER:** Mike ratification of (a) the fifth wire value, (b) kill-vs-retire, (c) the projection precedence (events hold truth; a different precedence is a projector-only change).

### D5. The mandate is immutable: deployment_criteria + structured gates freeze at deploy; criteria_digest is chain-anchored; change = retire + redeploy with lineage (*resolves the judge's top open tension; graft: criteria_digest*)

**Decision.** `deployment_criteria` (verbatim prose) and the `agent_criteria_gates` rows authored with it (D9) are **frozen at deploy**. `criteria_digest` = SHA-256 over the canonical serialization of (prose + ordered gate rows), stored on the registration and anchored in the DEPLOYED hash-chain entry (D14) — post-hoc mandate tampering is detectable via the existing `GET /decision-log/verify`. Changing the mandate is retire (orderly) + redeploy with `predecessor_registration_id` lineage; the old registration's audit trail closes intact and the new mandate gets its own chain anchor. **There is no amend-criteria verb.** The winning design's amend verb (evented, rationale-mandatory) was its self-flagged most invention-adjacent decision; the mandate is the accountable contract of the deployment, and a mutable mandate guts the audit defensibility that [EVIDENCE-GROUNDING] sells. Oversight-chain replacement (`OVERSIGHT_CHANGED`, before/after recorded) remains legal — accountability routing evolves; the mandate does not.

**Alternatives considered:** the amend-criteria verb with chain-mirrored CRITERIA_AMENDED entries (documented; viable if operational reality demands criteria evolution without redeploy ceremony — the criteria_digest mechanism would extend to amendments); mutable criteria without chain anchoring (rejected outright — undetectable mandate drift).

**REVISIT TRIGGER:** first engagement needing criteria evolution without redeploy — **explicit Mike decision required**; if granted, amendments must be chain-mirrored, never bare updates.

### D6. Honest control verbs: declared enforcement effect per execution_locus; runtime acknowledgment ≠ human confirmation; zombie agents are first-class observables (*graft: honest-scope product copy*)

**Decision.** Every registration carries `execution_locus ∈ {SUBSTRATE_MCP, ORCHESTRATOR, CUSTOMER_SYSTEM}`; from it the engine derives a per-verb `controlEffect` exposed in the detail DTO and in every verb response, so operators and Testers see what a click actually DOES before and after they click:

- **`GATEWAY_BLOCK`** (SUBSTRATE_MCP locus, once contracts 3c lands): the registry flip is the control plane — `ContractGateway` denies the agent principal's next governed call (D7).
- **`RECORDED_INTENT`** (ORCHESTRATOR / CUSTOMER_SYSTEM loci, and ALL loci during the 6b→6c window — D17): the state flip is the authoritative governance record; the outbox notifies the oversight chain; confirmation is tracked as a first-class pending state.

Honesty rules, binding on UI and product copy:
1. **Substrate never claims to have stopped what it cannot reach.** RECORDED_INTENT rows render "Paused — unconfirmed at runtime" until confirmation lands.
2. **Acknowledgment and confirmation are distinct facts.** A compliant runtime may call the `acknowledge_control` MCP tool — the ONE governed write a paused/retired agent principal is still permitted, since acknowledging shutdown is the compliant act — recording `CONTROL_ACKNOWLEDGED` ("the runtime has seen the order"). Human-attested `POST /agents/{key}/confirm-control` with evidence refs records `CONTROL_CONFIRMED` ("a human verified it stopped"). Neither auto-flips from the other; absence of sightings NEVER auto-confirms (it may render as a clearly-labeled weak positive: "no activity observed since pause (N days)").
3. **Sightings after pause/kill are recorded AND escalated, never rejected-and-forgotten.** A heartbeat or gateway call from a PAUSED agent: the sighting is recorded (it is true), the governed action is denied (enforce mode), and `CONTROL_VIOLATION_OBSERVED` + an `ACTIVE_WHILE_PAUSED` signal fire to the oversight chain. After kill: `SEEN_AFTER_KILL`, the highest-urgency signal class. The operator's worst case — a zombie agent — is a first-class observable. This is the entire point of P12.
4. **Verb responses carry the same honesty as the UI:** `{status, enforcement: {effect, confirmationState, disclosure}}` — acceptance-must-be-user-runnable applies to enforcement claims too.

**The honest claim, verbatim for product/sales/UI copy (mirrors ADR-002 D1's honest-scope paragraph; ships WITH the feature):** *"Every agent has a registration — substrate grants no agent write surface without one. Pause, throttle, and kill are enforced absolutely on everything that transits substrate; enforced at dispatch and at result-apply for substrate-initiated agent work; and published + acknowledgment- and confirmation-tracked for external runtimes, where non-adherence is an immediate, audited signal."* Never "all agent actions everywhere are blocked."

**Alternatives considered:** uniform "pause = blocked" semantics (rejected — fabricated control for two of three loci; the dishonesty P12 exists to prevent); confirmation auto-derived from sighting absence (rejected — absence of telemetry is not evidence of stoppage); no acknowledgment channel (the winner's original shape; rejected — for CUSTOMER_SYSTEM loci, "did the runtime even see the order" is a real, cheap, honest fact distinct from human confirmation).

**REVISIT TRIGGER:** Mike sign-off on the product-copy paragraph (follow-up #4-equivalent of ADR-002); first engagement deploying CUSTOMER_SYSTEM agents at scale (confirmation workflow ergonomics).

### D7. Gateway integration: `AgentRegistryGate` SPI with registry-first → contract-party carve-out → unregistered policy; one enforcement ladder, not two (*grafts; resolves judge open tension #3*)

**Decision.** The SPI interface `AgentRegistryGate` is declared in `engine.contract.gateway` **with a no-op default bean** (always allow-unflagged); `engine.agent` contributes the real `@Primary` implementation. `ContractGateway` invokes it for every `PrincipalType.AGENT` action BEFORE clause-guard evaluation — the "agent registry gating" extension point contracts.md §15 reserved, with the same built-in non-removable posture as the `waive_breach` guard (ADR-002 D16). Whole-or-in-part falls out by construction: contracts module without agents module = no-op gate; agents module without contracts module = no gateway exists, all verbs function as RECORDED_INTENT with the UI disclosing exactly that.

Resolution order for an AGENT principal:
1. **Registered agent** (`agent_registrations.mcp_principal_id` match): RETIRED/PAUSED ⇒ DENY (`AGENT_CONTROL_SUSPENDED`) + sighting + violation signal; SHADOW ⇒ only observation-scope tools allowed, others DENY/WOULD_DENY (`AGENT_SHADOW_SCOPE`) — P11's observation-only trial made structural; `read_only=true` denies mutating actionTypes (`AGENT_READ_ONLY`); throttle budgets checked against DB-backed rate counters (D12); LIVE + in-intervention ⇒ ALLOW + flag (`AGENT_IN_INTERVENTION`) — never brick the telemetry that diagnoses the problem.
2. **Contract-party carve-out:** no registration, but the principal matches `contract_parties.mcp_principal_id` ⇒ a legitimate P19 counterparty system; party-scoped contract verbs for their own party allowed; anything else treated as unregistered. A flat unregistered-DENY would brick legitimate federated parties (the winning design's one resolution bug — fixed by this graft).
3. **Unregistered:** reads + `check_action` always allowed (ungoverned by design). Governed writes: shadow mode ⇒ `ALLOW_WITH_FLAG(AGENT_UNREGISTERED)`; enforce ⇒ DENY. Every unregistered touch emits a signals row — "unknown agent knocking" is the P12 fleet-visibility product moment, surfaced not swallowed.

Enforcement mode rides the **single existing ladder** `substrate.contracts.enforcement.mode = off | shadow | enforce` — one ladder, not two; operators never face split-brain enforcement claims. Decisions row into the existing `contract_enforcement_decisions` log (no parallel log); registry-state reads are cached alongside `GuardCache` with the same invalidation + 30s TTL discipline (the contracts p50 < 5 ms budget now covers both lookups — perf assertion in the Testcontainers suite). Fail posture inherits ADR-002 D5 (AGENT fail-closed). Wire shapes for denial reuse ADR-002 §4.5 exactly (REST 409 envelope, MCP `isError` structured payload) with additive code `AGENT_GATE_DENIAL`.

**Alternatives considered:** a separate `substrate.agents.gateway-mode` ladder (the integration design; rejected — independent rollout is not worth split-brain claims; documented as the alternative); guard-source registration from `engine.agent` into the gateway without an SPI (the winner's shape; rejected — the SPI-with-default seam is cleaner and makes the no-op degraded case a bean, not a conditional).

**REVISIT TRIGGER:** first engagement needing agent gating to roll out on a different cadence than contract enforcement (would resurrect the second ladder); gateway p99 regression attributable to the registry lookup.

### D8. ORCHESTRATOR locus: dispatch preflight + result quarantine; the five-tool seam is NOT extended (*graft*)

**Decision.** For registrations with `execution_locus=ORCHESTRATOR`: any substrate component dispatching on the agent's mandate preflights registry state before `submit_task` — paused/retired agents get no new dispatches; throttle budgets pace submissions (composing with `check_budget_for_task`). An in-flight dispatch **cannot be aborted** — the consumed seam has exactly five tools and none cancel; stated plainly in UI disclosure. But its output is quarantined: the `apply_dispatch_result` PEP (already a governed action, ADR-002 D2 #3) consults the registry and **refuses to apply results attributable to a killed/paused registration** (DENY-shaped, evented). Kill = no new submissions + no re-entry of in-flight output into substrate. This is seam-legal (no new consumed tools) and upgrades ORCHESTRATOR locus from pure RECORDED_INTENT without touching the contract doc. Adding a cancel/pause consumption tool would not violate one-directionality but revises a ratified seam doc — **flagged Mike follow-up, do NOT wire unilaterally.**

**Alternatives considered:** extending the seam with a cancel tool now (rejected — seam doc revision without Mike); treating ORCHESTRATOR locus as fully RECORDED_INTENT with no quarantine (the winner's original; rejected — the quarantine is free, seam-legal, and closes the "kill, yet its output lands anyway" hole).

**REVISIT TRIGGER:** an engagement deploying orchestrator-run fleet agents that expects hard mid-flight control — the seam-revision conversation with Mike.

### D9. deploymentCriteria as a runtime gate: `agent_criteria_gates` reusing the contracts TinyDsl VERBATIM; signal-only, never auto-suspend (*graft; fills the winner's extension-point punt*)

**Decision.** The binding text "deploymentCriteria becomes a runtime gate (plan §5)" is delivered, not punted: each mandate clause lands as an `agent_criteria_gates` row — `gate_text` (verbatim prose clause), `rule_type ∈ {STRUCTURED, UNSTRUCTURED}`, `predicate` (JSON, **the contracts TinyDsl of ADR-002 D9/§4.4, reused verbatim — no second DSL**), `cadence`, denormalized `standing ∈ {UNEVALUATED, MET, AT_RISK, HUMAN_VERIFY_DUE}`. STRUCTURED predicates are evaluated on the shared contracts monitor scheduler against `agent_metric_samples` (push-based, idempotent upsert — ADR-002 D11/D13 idioms). Evaluation is **signal-only**: a failing predicate sets `AT_RISK` standing + a bounded `CRITERIA_STANDING_CHANGED` event + a signals/attention row suggesting intervention — **never auto-pause, never auto-kill** (cascade D5 principle: the system never speaks for a human in an accountability chain; an agent's suspension is an attributable human act). UNSTRUCTURED prose ("zero PHI leakage" — the canonical fixture example) emits a recurring `HUMAN_VERIFY_DUE` signal on its cadence — a gate can be weak but never silently inert (no-silent-zero-yield). INDETERMINATE (missing samples) never marks AT_RISK (ADR-002 D10 hard invariant carried over). Because predicates are the same DSL, a future contract guard can cite an agent gate (metric leaf over agent metrics) — recorded as the designed contracts↔agents composition path, not built. Whole-or-in-part: without the contracts module the TinyDsl evaluator is absent — STRUCTURED gates stand UNEVALUATED with a visible coverage signal; UNSTRUCTURED human-verify recurrence runs on the agent engine's own sweeper regardless.

**Alternatives considered:** the governance design's second predicate vocabulary (`criteria_spec` kinds: TARGET_METRIC/ESCALATION_SLA/SHADOW_WINDOW/SCOPE_LIMIT — rejected: violates the one-tiny-DSL discipline of contracts D9 and is the heaviest-build path); extension-point-only (the winner's punt; rejected — the plan §5 text is binding and the TinyDsl reuse makes delivery cheap); auto-intervention on missed targets (rejected for default — would land only as explicit per-agent policy, default off, if ever demanded).

**REVISIT TRIGGER:** first predicate the TinyDsl can't express (same revisit as contracts D9 = the port-map §4.5 JSONB flip condition); first engagement demanding auto-suspension policy.

### D10. Promotion: two-step, gated on a single-use compliance review + the `agent.promote` governed action; review-content semantics are flag-not-invent

**Decision.** SHADOW→LIVE is two evented steps: (1) `promote/request` records `PROMOTION_REQUESTED` with the shadow-window summary as payload, surfacing as promotion-pending; (2) `promote` executes ONLY when an unconsumed APPROVED `agent_compliance_reviews` row (kind=PROMOTION, newer than the request) exists — else 409 `PROMOTION_REVIEW_REQUIRED` — AND the promote itself transits `ContractGateway` as `actionType=agent.promote` (the contracts spec's own canonical guard example; its 3c acceptance already seeds an `agent.promote` DENY guard), so a compliance contract can structurally block promotion. The review row records reviewer identity, decision, rationale, evidence refs — **and nothing else: what "HIPAA validation before promotion" concretely requires is UNKNOWN; the review entity must not quietly encode invented compliance criteria** (flag-not-invent). REJECTED renders info/neutral and is re-requestable (decline-not-error, trap #8 applied to agents); NEEDS_MORE_TIME keeps the request open. Agents can never self-promote: lifecycle verbs are REST-only/human-only and `agent.promote` carries a built-in non-removable AGENT-deny guard (waive_breach D16 idiom).

**Alternatives considered:** reasoning-only promotion with review displayed-not-gating (the integration design; rejected — the fixture text "promotion to production gated on compliance/regulatory review" implies a gate, and the mechanism is concrete demo-beat material without inventing review content); hard shadow-window duration enforcement (rejected — window lengths are fixture narrative, not binding semantics; the window summary is review input).

**REVISIT TRIGGER:** first regulated promotion defines real review-content semantics — Mike session before encoding any.

### D11. Honest liveness: a separate sightings table; observability and staleness derived; last_seen_at only from real sightings or human attestation

**Decision.** `agent_sightings` is deliberately separate from `agent_status_events`: sightings are telemetry with a retention profile; events are the governance audit trail — mixing them would bloat the append-only audit and poison the D14 anchor seam. `last_seen_at`/`last_seen_via` are set ONLY by: GATEWAY_ACTION (governed call by the bound principal), HEARTBEAT (MCP tool), METRIC_REPORT, ATTESTATION (human "I verified this agent is running", with evidence), DISPATCH_EVENT (substrate-originated dispatch activity). Registration recency (`updated_at`) is NEVER conflated with liveness. The detail DTO carries a derived liveness block: `observability ∈ {OBSERVABLE, ATTEST_ONLY}` (from locus + principal binding), `staleness ∈ {FRESH, STALE, NEVER_SEEN, NOT_EXPECTED}` (STALE only when an expectation exists and is exceeded; `heartbeat_expected_minutes` NULL renders "not expected to report", never stale-red). UI rule, binding for the swap: the status pill is governance state; liveness renders as a separate line — never a fabricated green dot. `recentActivity` is derived at read (latest sighting detail, else latest lifecycle event, else "No activity observed") — never blank, never invented; `adherence` is nullable (the engine cannot honestly compute playbook adherence in v1; it fills from reported/attested metrics when present). Sightings are hourly-bucket-deduped and carry a retention config (first-engagement calibration, named risk).

**Alternatives considered:** liveness from row timestamps (rejected — fabricated green); sightings in the event log (rejected — volume poisons the audit trail); required adherence with a v1 formula (rejected — the formula exists nowhere; flag, don't fabricate).

**REVISIT TRIGGER:** first real adherence rubric (engagement-defined); sightings retention before any high-traffic engagement.

### D12. Throttle: first-class budget rows + DB-backed rate counters (explicit S12 lesson)

**Decision.** `agent_throttle_budgets` rows (validated-string `budget_kind`; one active per (agent, kind) via PG partial unique + service enforcement) are first-class indexed columns on the gateway hot path — never JSON predicates (ADR-002 D9 discipline). `ACTIONS_PER_WINDOW` is enforced against `agent_rate_counters` — atomic DB increments in the gateway check transaction; restart-safe and multi-instance-safe, **unlike CostTracker's in-memory atomics (the S12 lesson, applied)**. Budgets are agent-readable via MCP `get_my_control_state` for P11 client-side self-limiting ("rate-budgeted and client-enforced"). For non-substrate loci, budgets are published obligations whose exceedance (via reported metrics) is a signal, never a fabricated block. SCHEDULE_WINDOW / TOKENS_PER_DAY / SAMPLING_PCT kinds are schema-ready; only ACTIONS_PER_WINDOW gets an evaluator in 6c.

**Alternatives considered:** in-memory token bucket (the governance design; rejected — restart-lossy, multi-node-silent-weak; S12 is a named memory); rate config as JSON on the registration (rejected — hot-path JSON).

**REVISIT TRIGGER:** counter-row contention under high agent action volume (shared revisit with contracts decision-log retention).

### D13. Notifications: transactional outbox, same transaction, oversight-chain fan-out; escalation sweeper is notification-only

**Decision.** `agent_notifications` rows are written in the SAME transaction as the triggering event (ADR-001 D10 — never AFTER_COMMIT), fanning out to the ordered `agent_oversight_links` rows (the chain is a table, not JSON, precisely because it is the routing target). `AgentEscalationSweeper` (cascade D5 idiom verbatim: deterministic dedupe keys + DB UNIQUE backstop, renotify window/limit, NEVER a state transition) escalates two dwell conditions up the chain: unresolved interventions past `substrate.agents.intervention-escalation-days`, unconfirmed RECORDED_INTENT controls past `substrate.agents.control-confirm-timeout-hours`. Unifying with `cascade_notifications` is a flagged later refactor, not v1 coupling.

**REVISIT TRIGGER:** notification-table unification; channel adapters (Phase 5, same watermark pattern).

### D14. Hash-chain mirroring: bounded to DEPLOYED / PROMOTED / RETIRED, criteria_digest anchored in DEPLOYED; the mirror mechanism is shared with contracts D14, never forked (*resolves judge open tension #4*)

**Decision.** Exactly three event classes mirror into the existing `engine.decision` SHA-256 chain via `DecisionLogService` under its per-domain append lock: **DEPLOYED** (carrying `criteria_digest` — mandate creation becomes tamper-evident), **PROMOTED** (production entry), **RETIRED** (termination, carrying `retired_reason` so kill and orderly retirement are both chain-anchored — a regulated buyer wants termination tamper-evident either way). Chain inputs reference `agent_key` + UUIDs + stable actor ids, never display names ([DECISIONLOG-COVERAGE]). A pinned hash-vector test lands BEFORE enabling (port-map trap #3). **Coordination rule (binding):** contracts D14 designed mirror-entry typing but `engine.contract` does not exist on disk — whichever engine implements first lands the shared mirror-entry mechanism (canonical-JSON layout + additive `DecisionType` values) **in `engine.decision`, not in either consuming engine**; the second consumer reuses it. Building two mirroring stacks or diverging canonical layouts breaks chain verification — coordinate at dispatch. OVERSIGHT_CHANGED is NOT mirrored (high-frequency-adjacent operational act; lives in the trigger-protected append-only log).

**Alternatives considered:** mirroring every event (rejected — chain volume/lock contention, same as ADR-002 D14); mirroring OVERSIGHT_CHANGED (deferred — named regulated-buyer revisit); no mirroring (rejected — deploy/promote/kill are exactly the acts a regulated buyer wants tamper-evident).

**REVISIT TRIGGER:** regulated buyer demanding chained oversight-amendment custody; chain contention under combined cascade-attestation + contract + agent mirroring (shared revisit with ADR-002 D14).

### D15. Attention surface: AttentionItem-shaped agent signals + an app-module composed `/api/v1/attention` feed (*graft*)

**Decision.** The agent engine exposes `GET /agents/attention` emitting rows shaped exactly like the cascade engine's `AttentionItem` (`kind/tone/headline/since`): `agent-in-intervention` (destructive — leader-attention per resolved queue #21), `control-violation` (destructive), `agent-paused` (warn), `control-unconfirmed` (warn), `criteria-at-risk` (warn), `human-verify-due` (info). An app-module `AttentionController` (`GET /api/v1/attention?domainId`) composes `CascadeQueryService.attention` + the agent feed into one list — **[CASCADE-PROPAGATION]'s "decline-pending cascades render beside in-intervention agents" becomes a single API call**, not a UI-zone convention. Engines stay decoupled (read-side composition, zero engine-to-engine writes — contracts §11.2 posture); no cascade is ever auto-authored from an intervention (queue #24 gate respected).

**REVISIT TRIGGER:** queue-#24 session reshaping the attention surface.

### D16. MCP surface: extend the one `/mcp` server; agents read their own mandate; no self-administration, ever

**Decision.** No second MCP server. The existing `substrate-contracts` server (ADR-002 D8 hosting) gains: read tools (ungoverned) `list_agents`, `get_agent`, `get_my_registration` (caller-identity-resolved — my mandate, my gates + standing, my status, my oversight chain; sibling of `get_obligations_for_principal`; the precondition for P19 adherence-is-observable applying to agents themselves), `get_my_control_state` (mode + budgets + schedule — the P11 self-limiting read). Governed writes: `agent_heartbeat(activity_summary?)`, `report_agent_activity(activity_note?, metrics?)`, `acknowledge_control` (the one write a suspended principal retains — D6), plus the existing `report_metric` resolving agent principals. **Never MCP-exposed:** deploy/promote/pause/resume/throttle/kill/retire/intervention — REST-only, human-only; an agent can never operate the kill switches, including its own (structural: no tools exist + actor_type on lifecycle events excludes AGENT + built-in guards). One server = one principal model, one gating config, one Phase-5 hardening path.

**Alternatives considered:** separate agents MCP server (rejected — doubles identity/config surface for ~7 tools; revisit if the toolset grows past ~a dozen or needs distinct authz); REST-only (rejected — breaks `get_my_registration` ergonomics and P19's agents-join-by-speaking-MCP posture).

**REVISIT TRIGGER:** toolset growth; Phase 5 OIDC client-credential binding (column exists; no schema change).

### D17. **Decision.** Strict read-model-first per the port-map D3 row: 6a and 6b are parallel-ok with D1/D2 chunks; 6c is sequential after contracts 3c lands the gateway. **Between 6b and 6c, ALL verbs are RECORDED_INTENT even for SUBSTRATE_MCP-locus agents** — the port-map tolerates stubbed verbs, but operators must not over-trust pause: the detail DTO carries `enforcement.disclosure = "enforcement pending gateway"` for that window, and **a curl acceptance in 6b asserts that field** — disclosure is an acceptance item, not a note. The OperationsTab adapter changes (null adherence → em-dash, derived recentActivity, always-present provenance line) land WITH the 6a swap or rows render broken. Every phase has curl-runnable acceptance (spec §16); Testcontainers-Postgres is the gate; H2-green is never acceptance.

**REVISIT TRIGGER:** none — sequencing is binding; only the 6b internal slice points may flex.

### D18. DemoPack: action-stream replay through the real lifecycle service; seed-only fiction is flagged and never ships

**Decision.** `AgentDemoSeeder` (gated `substrate.demo.seed`, isDemo domain only) drives the real lifecycle service with the injectable fixed clock (cascade D16 idiom — the seed IS a standing state-machine integration test): deploy every fixture agent from the nine subsidiary files, promote the `live` ones, pause with fixture reasons, open interventions with fixture drift narratives, seed fixture `recentActivity`/`adherence` as sightings/metric samples so the engine computes what the fixture stamped. ## 4. Consequences

**Positive.**
- P12's claim is structurally honest at every locus: every verb yields an attributed event + authoritative state change + a *declared, disclosed* enforcement effect; zombie agents (`ACTIVE_WHILE_PAUSED`, `SEEN_AFTER_KILL`) are first-class observables; Testers get the same honesty as the UI in every verb response.
- A provenance-less agent cannot exist (NOT NULL columns + deploy gate), the mandate is immutable and tamper-evident (criteria_digest in the chain), and unregistered agent principals have no write surface inside substrate — the registry-gating keystone — while legitimate contract parties are carved out.
- The two-dimensional state model preserves verified fixture truth (in-intervention agents keep operating); the wire projection speaks exact fixture vocabulary so OperationsTab swaps without rework, and the pill-map crash is mitigated by default RETIRED exclusion.
- deploymentCriteria is a real runtime gate (TinyDsl-verbatim, signal-only) without a second DSL, preserving the future contract-guard-cites-agent-gate composition.
- Pause/kill/retire/decline-shaped outcomes are never error-colored anywhere (200s, warn/neutral tones, REJECTED review renders info).
- Whole-or-in-part holds by construction (SPI no-op default; zero orchestrator touchpoints in the engine; degraded = recorded-intent with disclosure).
- One focused build on ratified idioms: cascade D1/D5/D8/D9/D10/D11/D13/D16 and contracts D4/D5/D9/D10/D11/D13/D14/D16 are reused, not reinvented.

**Negative / accepted risks.**
- RECORDED_INTENT can be mistaken for interception by operators and sales copy — the D6 honest-scope paragraph must ship with the feature and survive into compliance conversations; locus-unqualified "killable" claims would be fabricated control.
- The fifth wire value (`retired`), kill-vs-retire, and the projection precedence are synthesis beyond the binding four states — top Mike-ratification items; all are projector-level changes if overruled.
- Mandate immutability may prove operationally rigid (retire+redeploy ceremony for a criteria tweak) — explicit revisit with Mike before any amend verb lands.
- ORCHESTRATOR-locus agents have no mid-flight control (five-tool seam has no cancel); kill stops new submissions and quarantines results, and a long-running dispatch keeps consuming budget after kill — stated plainly, seam revision is Mike's call.
